# Phase 29 — Demo Video & Submission Packaging

> Record the demo flow, assemble submission assets, and prepare the final Devpost/app listing package.

---

## Context

The video should prove the hook quickly. Do not make a feature tour. Show community-shaped tower, one jump, one fall, visible mutation, and a retention/result beat.

---

## What This Phase Builds

### Video Script

Target 45-90 seconds:

1. Open on the first viewport with failed-climbs headline.
2. Point out visible artifacts through gameplay, not narration-heavy overlays.
3. Make a jump and fall.
4. Show the mutation feedback and artifact/badge change.
5. Clear a checkpoint or show stabilization.
6. Show result card/tomorrow hook.

### Capture Requirements

Record:

- desktop flow
- short mobile clip if possible
- no developer console
- no debug labels
- no demo-mode labels

### Submission Assets

Prepare:

- final app title and short description
- screenshots
- demo video link/file
- public demo post link
- feedback log summary
- concise feature list focused on shared mutation, daily tower, and Devvit interactive post

### Devpost Copy

Emphasize:

- community mutation
- daily shared state
- failure helping and distorting
- Reddit-native discussion material
- Phaser/Devvit implementation

Avoid generic "fun platformer" framing.

---

## Key Technical Considerations

- Make the first 10 seconds of the video carry the hook.
- Use real app footage, not mockup footage, for final submission.
- Keep all claims aligned with what is actually implemented.
- Include exact demo post link once human posting is complete.

---

## How to Know It's Working

- The video shows the hook before any detailed explanation.
- Submission package has app listing copy, screenshots, demo link, and video.
- No debug or placeholder artifacts appear.
- Claims in the submission match the build.
