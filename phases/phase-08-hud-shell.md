# Phase 08 — HUD Overlays, Mobile Controls & Devvit Shell

> Build the UI layer that wraps the game — the header bar, HUD overlays, mobile control buttons, charge indicator, mutation banner, checkpoint banner, and controls hint. The shell that makes the game playable and informative.

---

## Context

The Phaser game renders the tower and the player. But the player still needs to know where they are, what zone they're in, how many times they've fallen, and — on mobile — needs touch controls to actually play. This phase builds the DOM shell that sits on top of the Phaser canvas: branded header, live stats, mobile input, and the overlay banners that deliver feedback.

The architecture split is clear: **Phaser owns the game world, the DOM shell owns the UI.** The shell doesn't reach into Phaser's scene graph, and Phaser doesn't render buttons or text overlays. DOM controls and Phaser share a local input store/module in the client; persistent state still goes through Devvit Web `/api` endpoints.

The mockup (`mockup(3).html`) has all of these elements implemented and styled. The job here is extraction and integration, not invention.

## What This Phase Builds

### Header Bar

A branded bar across the top of the viewport:

- **Hanko stamp**: a small persimmon-colored square containing the character `登` (climb). Positioned left. This is the game's logo mark.
- **"Fallstack" wordmark**: rendered in **Shippori Mincho** font. The word "Fall" in dark text, "stack" in persimmon. Positioned after the hanko stamp.
- **Headline**: dynamic text reading `"X travelers slipped on this mountain today"` where X is the total fall contribution count across all zones. This count updates as falls are recorded.

The header bar uses the washi paper styling: `background: rgba(247,240,226,0.88)`, subtle `box-shadow`, slight transparency to let the game world peek through at the edges.

### Zone Tag HUD (Top-Left)

Displays the current zone name and its community badge:

- **Zone name**: e.g., "Moss Steps", "Iron Bell", "Moon Shelf"
- **Badge**: a small colored pill/chip next to the zone name

Badge display uses a friendlier vocabulary than the internal state names:

| Internal State | Display Badge | Badge Color |
|---|---|---|
| Quiet | Untouched | `#e7e2d1` (warm grey) |
| Haunted | Restless | `#e6d3d8` (dusty pink) |
| Cursed | Overgrown | `#5c4a63` (deep purple, light text) |
| Reinforced | Well-Trodden | `#dbe6d1` (sage green) |
| Stabilized | Blessed | `#d7e6df` (cool mint) |

The zone tag updates as the player crosses zone boundaries (detected by the camera/player Y position).

### Stats HUD (Top-Right)

A compact stats display:

- **Climbs**: total successful zone clears this session
- **Falls**: total falls this session
- **Checkpoint progress**: e.g., `"0/3"` — how many of the three zone checkpoints have been reached

These update in real time as events fire from the Phaser game into the client state store.

### Mobile Controls Bar (Bottom)

A fixed bar at the bottom of the viewport, **88px tall**, containing three touch buttons:

**Left Arrow Button**
- Size: 62×62px
- Shape: rounded rectangle
- Content: left arrow icon (← or SVG)
- Touch behavior: **hold-to-activate** — the control is active as long as the finger is down

**Jump Button (Center)**
- Size: flexible width, maximum 220px
- Shape: rounded rectangle, wider than directional buttons
- Content: text "HOLD" (or "SPACE" on desktop)
- Touch behavior: **hold-to-charge, release-to-jump** — mirrors the keyboard space bar
- **Charge fill overlay**: a colored fill that grows from 0% to 100% width inside the button as the player charges. Uses the current zone's glow accent color.

**Right Arrow Button**
- Size: 62×62px
- Shape: rounded rectangle
- Content: right arrow icon (→ or SVG)
- Touch behavior: **hold-to-activate**

**All buttons share:**
- Pressed state visual: `translateY(2px)` shift and reduced `box-shadow` to simulate physical depression
- Washi paper styling consistent with the header bar
- Touch event handling: `touchstart`/`pointerdown` activates, `touchend`/`pointerup`/`pointerleave` deactivates
- Multi-touch support: the player must be able to hold a direction AND hold jump simultaneously

### Input Forwarding

The mobile controls don't directly call Phaser scene methods. Instead, they maintain a shared **input state object** that Phaser reads each frame:

```
inputState: {
  left: boolean,
  right: boolean,
  jump: boolean    // true while held, false on release
}
```

The Phaser game reads this state the same way it reads keyboard state — checking `isDown` flags each frame. This means the game logic doesn't need to know whether input comes from keyboard or touch.

### Mutation Banner (Bottom Overlay)

An overlay that appears above the mobile controls after a fall:

- **Position**: bottom of viewport, above the controls bar
- **Content**: mutation feedback text (generated by the mutation feedback system in Phase 11)
- **Styling**: washi paper background, **persimmon left border accent** (4px solid left border), compact text
- **Animation**: slides in with `opacity 0→1` + `translateY(10px→0)` transition
- **Auto-hide**: fades out after approximately **3.6 seconds**
- **Stacking**: if a new mutation event fires while a banner is showing, replace the current banner (don't stack multiples)

### Checkpoint Banner (Center Overlay)

An overlay that appears when the player clears a zone and reaches a checkpoint:

- **Position**: center of viewport
- **Content**:
  - Cleared zone name + zone status (e.g., "Moss Steps noted your care")
  - Subtitle with clear count and next zone preview (e.g., "4 clean climbs tended this slope · Next: Iron Bell, Untouched")
- **Styling**: larger than mutation banner, centered, washi paper background
- **Animation**: fade in/out
- **Auto-hide**: disappears after approximately **3.2 seconds**

### Controls Hint Text

A subtle text line near the bottom of the viewport:

- Content: `"Arrows move & steer midair · Hold Space · Release to leap"`
- Styling: small font, low opacity, doesn't compete with controls or banners
- Visibility: always visible on desktop, can be hidden on mobile (where the touch buttons are self-explanatory)

## Key Technical Considerations

### DOM Overlays, Not In-Canvas UI

All HUD elements are **HTML/CSS elements positioned over the Phaser canvas**, not rendered inside Phaser's scene. This is intentional:

- DOM text rendering is crisper than canvas text, especially for small UI copy
- CSS transitions handle banner animations without game loop involvement
- Touch event handling on DOM buttons is more reliable than Phaser input zones at the edges of the viewport
- The Devvit webview hosts both the canvas and the DOM — they coexist naturally

### Fonts

Two Google Fonts:
- **Shippori Mincho**: serif, used for the wordmark, zone names, and headline text
- **Zen Maru Gothic**: rounded sans-serif, used for body text, stats, button labels

Load these via `<link>` in the webview HTML or via `@import` in CSS. They need to be available before first render to avoid font flash.

### Input State, Not Input Events

The mobile controls must forward **state**, not **events**. The game needs to know "left is currently held" — not "left was tapped 200ms ago." This means:

- On `pointerdown`: set `inputState.left = true`, send state
- On `pointerup`: set `inputState.left = false`, send state
- The Phaser game checks the latest state each frame, same as `cursors.left.isDown`

This avoids timing issues where press/release events get lost or arrive out of order.

### Washi Paper Styling

The consistent styling for all HUD elements:

```css
background: rgba(247, 240, 226, 0.88);
border-radius: 8px; /* varies by element */
box-shadow: 0 1px 4px rgba(0,0,0,0.08);
font-family: 'Zen Maru Gothic', sans-serif;
color: #3a2e1f;
```

This gives everything a stamped-on-paper quality consistent with the "compact cursed diorama" aesthetic.

### Responsive Layout

The game targets mobile-first (Devvit interactive posts are primarily viewed on phones). The controls bar is fixed at the bottom, the header is fixed at the top, and the Phaser canvas fills the space between. On wider viewports (tablet, desktop), the controls bar can be hidden or made optional since keyboard input is available.

## How to Know It's Working

- The game has a branded header bar with the hanko stamp, wordmark, and headline
- The headline shows a traveler count that increases after falls
- The zone tag in the top-left shows the current zone name and badge, and updates when crossing zones
- Stats in the top-right show climbs, falls, and checkpoint progress, updating in real time
- On mobile: holding the left button moves the player left, holding the right button moves right
- Holding the jump button charges — the charge fill grows visually inside the button
- Releasing the jump button launches the player
- The player can hold a direction and jump simultaneously (multi-touch)
- After a fall, the mutation banner slides in from the bottom with feedback text, then fades after ~3.6s
- After clearing a zone, the checkpoint banner appears center-screen with zone status info, then fades after ~3.2s
- All UI elements have the washi paper styling — they feel like part of the game's visual world, not generic UI chrome
