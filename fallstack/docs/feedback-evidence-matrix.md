## Evidence gaps to pursue

1. Extend hosted persistence only with ethically clean state: a fresh uncapped contribution, genuinely earned clear/summit, and response-loss recovery remain. Real logged-out `loid` needs a public/otherwise accessible test installation; the current Mac reaches Reddit but `r/fallstack_dev` is private. Existing authenticated probes and two-client reconciliation already cover the claims used in the form.
2. Repeat host performance measurements on physical mobile hardware and broader networks. The three same-version v0.0.15 cold/warm runs are direct evidence, but remain one VM rather than a population benchmark.
3. Compare the Safari playtest bridge on an authenticated supported Chromium/Firefox profile or obtain an official browser-support statement. Current evidence is intentionally Safari-only.
4. Continue error discoverability with a deliberate, non-destructive server exception. Successful hosted responses expose no opaque correlation header and CLI logs provide no automatic request record; an actual server exception is still needed to inspect platform error metadata.
5. If time permits, gather first-hand support evidence after explicit approval. Until then, keep the support rating neutral (3/5), explicitly low-confidence, and avoid response-quality claims.

## Research-backed framing

- Previous Feedback Award winners were described by Reddit as providing “especially insightful, thorough, and specific” survey responses. This matrix optimizes for those qualities through evidence, not answer length: [Games and Puzzles winners announcement](https://www.reddit.com/r/Devvit/comments/1hvz8s8/announcing_the_games_and_puzzles_hackathon_winners/).
- Current official docs say local testing is intentionally incomplete and normal development uses an uploaded playtest subreddit: [Devvit FAQ](https://developers.reddit.com/docs/guides/faq).
- Current official docs advertise `@devvit/test` as a production-like isolated backend with supported Redis and partial Reddit API coverage: [Testing with @devvit/test](https://developers.reddit.com/docs/guides/tools/devvit_test).
- Current playtest docs say the `?playtest=<app>` URL streams client logs and triggers live reload: [Playtest](https://developers.reddit.com/docs/guides/tools/playtest). Direct Safari verification found the local WebSocket bridge blocked as mixed content while the app itself rendered.
- The current configuration page's 16-character app-name limit and `devvit build` recommendation conflict with the live schema/current CLI: [Devvit configuration](https://developers.reddit.com/docs/capabilities/devvit-web/devvit_web_configuration), [changelog](https://developers.reddit.com/docs/changelog).
- The official changelog still ends at 0.13.6 although stable 0.13.7 and 0.13.8 are available from npm: [changelog](https://developers.reddit.com/docs/changelog).
- Current first-party React and Phaser templates were audited at pinned revisions; both install the same high-severity `tmp@0.0.33` path through the Devvit CLI. The same path persists in 0.13.8, and a targeted Inquirer 9.3.8 override audited at zero.
